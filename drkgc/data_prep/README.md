# DrKGC — Step 1: Data Preparation

Turns PrimeKG (as loaded by `pyg_implementation/txgnn`) into the inputs the
DrKGC-style pipeline needs:

1. `(drug, indication, disease)` and `(drug, contraindication, disease)` triple
   tables with both numeric ids and human-readable names;
2. an **entity-safe random split** of each of those relations;
3. an **auxiliary/context graph** of mechanism relations only (drug-target,
   gene-disease association, PPI) with an explicit leakage check;
4. a **degree-capped** copy of that context graph, plus the gene/protein degree
   distribution it was derived from.

Nothing in `pyg_implementation/` is modified — this package only reads from it.
Steps 2+ of DrKGC (candidate ranker, rule mining, subgraph retrieval, GCN
adapter, prompting, LLM fine-tuning) are **not** implemented here.

---

## Running it

From the repository root:

```bash
# everything, in order
python -m drkgc.data_prep.run_all --out-dir drkgc/data
```

`--data-folder` is the folder holding `kg.csv` / `kg_directed.csv`. It defaults
to whichever of `data/kg` or `data` actually contains them (the official PrimeKG
release unpacks into `data/kg`; `$TXGNN_DATA_FOLDER` overrides the detection),
so it normally does not need to be passed.

If `kg.csv` is missing it is downloaded from Harvard Dataverse. If
`kg_directed.csv` is missing it is generated by TxGNN's own `preprocess_kg` —
**budget tens of minutes and several GB of RAM for that first pass** on the full
8.1 M-row PrimeKG (it does a row-wise `apply` over the homogeneous relations);
it is written next to `kg.csv` and reused forever after.

Then verify:

```bash
python -m drkgc.data_prep.test_sanity --out-dir drkgc/data
```

`test_sanity` exits non-zero if any check fails.

### Useful flags

| Flag | Default | Meaning |
|---|---|---|
| `--split` | `random` | split strategy; the swap point for the future `disease_area` split |
| `--fracs` | `0.90 0.05 0.05` | train / valid / test fractions |
| `--seed` | `42` | seeds the shuffle *and* the degree-cap subsampling |
| `--on-violation` | `reassign` | what to do with entity-unsafe valid/test triples (`reassign` to train, or `drop`) |
| `--cap` | *unset* | explicit gene/protein degree cap; overrides `--percentile` |
| `--percentile` | `95` | percentile of the degree distribution used as the cap |
| `--relations` | `indication contraindication` | target relations to extract/split |
| `--aux-relations` | `drug_protein disease_protein protein_protein` | relations forming the context graph |
| `--no-pyg` | off | write only CSV artifacts (skips the torch/PyG import) |

### Running the stages individually

Each module is also a standalone entry point, in this order:

```bash
python -m drkgc.data_prep.extract_triples     --out-dir drkgc/data
python -m drkgc.data_prep.split_random        --out-dir drkgc/data
python -m drkgc.data_prep.build_context_graph --out-dir drkgc/data
python -m drkgc.data_prep.degree_cap          --out-dir drkgc/data --percentile 95
python -m drkgc.data_prep.test_sanity         --out-dir drkgc/data
```

`python -m drkgc.data_prep.kg_loader` prints the node-type and relation
inventory without producing anything — handy for a first look.

### Column layouts

**Triple tables and splits** (identical columns — a split is just a row subset):

| column | meaning |
|---|---|
| `relation` | `indication` or `contraindication` |
| `head_type`, `tail_type` | always `drug` / `disease` |
| `head_idx`, `tail_idx` | per-node-type integer index — the same index space as TxGNN's `HeteroData` |
| `head_id`, `tail_id` | raw PrimeKG id (string; merged disease nodes look like `'1234.0_5678.0'`) |
| `head_name`, `tail_name` | human-readable drug / disease name, for LLM prompts |

**Context edge list** (`context_edges*.csv`): `relation`, `head_type`,
`head_idx`, `head_id`, `tail_type`, `tail_idx`, `tail_id`. Only the stored
direction is kept — add reverse edges at message-passing time if the GCN needs
them. `num_nodes` in the `HeteroData` follows TxGNN's rule (max index in the
full KG + 1) so indices remain interchangeable with the TxGNN graph.

Loading the PyG graph:

```python
from drkgc.data_prep.build_context_graph import load_context_graph
g = load_context_graph('drkgc/data/context_graph/context_graph_capped.pt')
```

(uses `weights_only=False`, which torch ≥ 2.6 requires for a `HeteroData` pickle.)

> `drkgc/data/` is untracked by git: the repository's root `.gitignore` ignores
> any `data/` directory. That is intentional — everything here is regenerable
> with one command.

## Summary statistics

### Expected sizes

The pipeline has **not been executed in this working copy** (no torch/pandas
here), so `drkgc/data/` is empty. The numbers below were measured by streaming
the real `data/kg/kg.csv` (8,100,498 rows) while emulating TxGNN's
`preprocess_kg`, so they are what a run should produce — treat them as a
reference to check the first run against, not as output of one. Derivation and
method are in `NOTES.md §6`.

| | `indication` | `contraindication` |
|---|---|---|
| triples extracted | 9,388 | 30,675 |
| unique drugs / diseases | 1,801 / 1,363 | 1,263 / 1,195 |
| split 90/5/5 before entity safety | 8,449 / 469 / 470 | 27,608 / 1,534 / 1,533 |

Train sizes end up slightly larger (and valid/test slightly smaller) once
entity-unsafe triples are reassigned; `split_stats.json` reports exactly how
many moved. The 9,388 indication triples match the count the DrKGC paper reports
for its PrimeKG subset.

Auxiliary graph: 25,653 `drug_protein` + 80,411 `disease_protein` + 321,075
`protein_protein` = **427,139 edges** over 19,051 gene/protein nodes.
Incident gene/protein degree: min 1, median 20, mean 39.3, p90 89, **p95 134**,
p99 316, **max 5,198** — 950 nodes sit above the p95 cap, so capping at 134
removes on the order of 10–25 % of the auxiliary edges. Leakage is expected to
be 0 by construction (the auxiliary relations connect different node types than
the targets).

### Where each statistic is written

Every number is emitted by `run_all.py` and persisted; the table lists where to
read each one after a run.

| Statistic | Printed by | Persisted in |
|---|---|---|
| KG size, node types, relation inventory | stage 1–2 | `kg_inventory.json` |
| Triples per target relation, unique drugs/diseases, unnamed entities | stage 2 | `triples/triple_stats.json` |
| Split sizes + achieved fractions, unique drugs/diseases per split | stage 3 | `splits/<relation>_split_stats.json` → `sizes`, `fractions`, `unique_heads`, `unique_tails` |
| Triples reassigned/dropped by the entity-safety constraint | stage 3 | same file → `entity_safety`, plus `sizes_before_entity_safety` |
| Residual entity-safety violations (must be all zeros) | stage 3 | same file → `entity_safety_violations` |
| Leakage check result | stage 4 | `context_graph/leakage_check.json` → `passed`, `num_overlapping_pairs`, `forbidden_relations_present` |
| Context graph size per relation | stage 4 | `context_graph/context_graph_meta.json` |
| gene/protein degree distribution (min / median / mean / p90 / p95 / p99 / max) | stage 5 | `context_graph/degree_stats.json` → `degree_stats_before` |
| Chosen cap, nodes over cap, edges removed, post-cap distribution | stage 5 | same file → `cap`, `num_nodes_over_cap`, `num_edges_removed`, `degree_stats_after` |
| Drugs/diseases that lost all context edges to capping | stage 5 | same file → `num_*_nodes_isolated_by_capping` |
| All of the above in one place | end of run | `step1_report.json` |

`run_all.py` also prints a compact summary block at the end (split sizes per
relation, leakage PASSED/FAILED, cap value and max-degree before → after).

## Design notes

* **Entity safety.** After the 90/5/5 shuffle, valid/test triples whose drug or
  disease is unseen in train are moved into train (`reassign`, the default) or
  dropped. Because reassigning only ever *adds* entities to train, one pass in
  shuffled order establishes the invariant. `test_sanity` re-derives it from the
  written CSVs rather than trusting the run.
* **Swappable split.** `split_base.py` defines the contract (`SplitResult`,
  `enforce_entity_safety`, `compute_split_stats`, `SPLIT_REGISTRY`);
  `split_random.get_random_split` is one implementation, registered as
  `'random'`. A future `split_disease_area.get_disease_area_split` with the same
  signature registers as `'disease_area'` and is selected with
  `run_all.py --split disease_area`. See `NOTES.md §4` for where TxGNN's
  existing disease-area logic lives.
* **Degree capping.** Degree is *incident* degree in the auxiliary graph (every
  edge touching the node, any relation, either orientation). Nodes are processed
  in descending-degree order and their remaining incident edges are randomly
  subsampled to the cap with a fixed-seed RNG; since removals only lower
  degrees, one pass leaves every gene/protein node at or below the cap. Both the
  uncapped and capped graphs are kept.
* **Leakage check.** Two independent checks: no drug–disease relation name
  (`indication`, `contraindication`, `off-label use`) appears among the
  auxiliary relations, and no target `(drug, disease)` endpoint pair appears as
  an auxiliary edge in either orientation. Both are expected to be trivially
  clean; the point is to prove it rather than assume it.
